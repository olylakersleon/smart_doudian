# 抖店商家 ClawBot 技术方案（动态自动化 Bot）

## 1. 目标

把诊断流程升级成“自动化运行的 Bot”：

- 在后台长期驻留；
- 不是无时无刻执行重任务；
- 基于规则 + LLM 动态判断“什么时候该跑一次巡检诊断”。

## 2. 架构新增

在已有「抓取-解析-诊断-LLM增强」链路上新增：

1. **AutoRunDecisionAgent**
   - 输入：上次运行时间、最近健康分、风险摘要、LLM摘要。
   - 输出：`should_run` + `reason`。

2. **Dynamic Bot Loop**
   - 固定 tick 轮询（轻量）。
   - 仅在决策通过时触发一次重诊断流程。

## 3. 动态触发策略

优先级顺序：

1. 首次运行触发。
2. 超过最大间隔强制触发（保底巡检）。
3. 未达最小间隔跳过（防止频繁跑）。
4. 近期健康分波动超过阈值触发。
5. 可选 LLM 决策触发（基于上下文判断）。
6. 默认跳过。

## 4. 为什么更像 OpenClaw 风格

- 持续驻留（Bot loop）
- 异步触发重任务（并非全时高频）
- 使用 LLM 参与调度策略（不仅做结果分析）

## 5. 数据落库

- `diagnosis_reports`：保存 health_score、风险、建议、LLM摘要。
- 调度判断依赖历史诊断结果进行动态决策。

## 6. 后续可扩展

- 接入消息队列（Kafka/RabbitMQ）作为事件触发源。
- 将 AutoRunDecisionAgent 替换为在线学习策略。
- 按业务场景区分轻巡检 / 深度巡检两个运行等级。


## 7. Tool 化分析层（新增）

系统支持按职责拆分诊断 tools，并在每轮诊断自动编排执行：

- 流量/转化诊断 tool
- 退款/履约诊断 tool
- ROI/竞品诊断 tool
- 问题知识检索 tool（将具体问题发送到 GPT/Gemini 获取 SOTA 信息）

这样可以把“问题知识获取”和“数据诊断”解耦，提高可维护性与分析准确度。


## 8. KDTS 协议化元工具生成（新增）

为了避免手写每个诊断工具，系统引入 KDTS 元工具工厂：

- 阶段1 知识结晶：根据具体问题提取诊断维度（name/metric/criteria/root_causes/advices）
- 阶段2 策略映射：为每个维度标注 deterministic / semantic
- 阶段3 工具合成：生成运行时工具 `RuntimeGeneratedDiagnosticTool`
- 阶段4 自检封装：自动生成自检样例（self_test_cases）

该机制使系统能够围绕不同问题快速“合成”新工具，并立即纳入主诊断编排。


## 9. Web 对话操作模块（新增）

新增 AutoWeb 模块，支持“用户自然语言 -> 页面动作执行计划”：

- 页面解析：识别页面框架与关键控件（搜索框、按钮、表格行、详情按钮）
- 意图理解：基于规则 + 可选LLM，将对话转为 action/filters
- 动作规划：根据框架适配器输出 click/type/observe 等步骤
- 执行层：支持 dry-run，后续可替换为真实浏览器执行

应用示例：在订单管理页面，用户说“查看订单号 XXX 的详情”，模块会自动生成输入订单号、点击搜索、点击详情的操作链。
